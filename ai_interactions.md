# AI Interactions Log

This file documents the **Agentic Workflow** stretch feature: TuneScout's plan → act → recommend → check → retry agent ([`src/agent.py`](src/agent.py)), plus its saved reasoning traces.

- **All traces from the latest evaluation run:** [`reports/agent_traces.md`](reports/agent_traces.md), generated by `python -m src.evaluate --only agent`.
- **Live traces from the CLI:** `python -m src.main --agent --trace "<request>"`. Every agent run is also appended to `logs/agent_traces.jsonl`.

---

## What the agent does

Plain RAG searches with the listener's exact words. It fails on negation ("NOT sad") and on words that aren't in the guides ("fall asleep", "funeral"). The agent adds a planning step, tools, and a self-check:

| Step | Who does it | What happens |
|---|---|---|
| 1. **Plan** | Gemini | Rewrites the request as a structured plan: search words, moods/genres to look for, moods to **avoid**, and an **energy range**. Labels it makes up are thrown out, and energy values are kept between 0 and 1. |
| 2. **Act** | Python tools | `search_catalog(query)` runs TF-IDF retrieval. `find_by_label(moods, genres)` looks up songs by exact label. `apply_constraints(plan)` removes songs that break the plan *before* Gemini sees them. |
| 3. **Recommend** | Gemini | Picks songs from the remaining candidates only, using the plan as extra context. |
| 4. **Check** | Python | Checks every pick against the plan (avoided moods, energy range). |
| 5. **Retry** | Gemini + Python | If a pick breaks the plan, Gemini is told which rule it broke and tries once more. Any pick that still breaks a rule is removed. |

If the planner fails (quota, network, bad JSON), the agent falls back to plain RAG. The trace records that too.

## Trace 3: "music for a funeral" (agent: FAIL, and why)

The planner's first two picks fit well. But it also listed the *chill* mood, and the plan can only express **energy** and **moods**, not "not upbeat". So *Library Rain* (chill lofi, valence 0.60) passed the agent's own check but failed the evaluation rule (valence < 0.6). The fix would be adding a valence range to the plan format. I left it as a documented failure instead of loosening the rule.

Full trace: [`reports/agent_traces.md`](reports/agent_traces.md#music-for-a-funeral).

## The retry loop

Real Gemini runs didn't break the plan, because the constraint tool already removes rule-breaking songs. So the retry path is proven by an offline test instead. [`tests/test_agent.py::test_rule_breaking_pick_is_retried_then_removed`](tests/test_agent.py) disables the constraint tool so a sad song reaches the LLM. It then checks four things:
- The first check flags the sad song.
- The feedback "Your previous answer broke the plan…" is sent to Gemini.
- A second attempt runs.
- The pick that still breaks the rule is removed.
